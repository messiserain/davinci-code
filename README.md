# 다빈치 코드 온라인

보드게임 "다빈치 코드"를 2~4명이 네트워크로 함께 하는 **온라인 숫자 추리 대전 게임**이에요.
상대가 숨겨 둔 숫자 타일을 먼저 모두 밝혀내는 사람이 이겨요.

| 항목 | 내용 |
| --- | --- |
| 형태 | 네트워크프로그래밍 2인 팀 프로젝트 |
| 팀 | stim (고제윤, 임재윤) |
| 사용 기술 | Java 21 (소켓, 스레드, Swing) |
| 오픈소스 | 쓰지 않아요. 서버와 클라이언트 코드를 모두 직접 작성하고, JDK 표준 라이브러리만 써요 |
| 진행 상황 | 접속·닉네임·채팅·귓속말 완성, 게임 진행 개발 중 |

## 게임 규칙

1. 0~11 숫자가 적힌 검은 타일 12개와 흰 타일 12개, 모두 24개를 써요.
2. 2~3인은 4개씩, 4인은 3개씩 받아요. 숫자가 작은 순서로 왼쪽부터 세우고, 숫자가 같으면 검은 타일이 왼쪽이에요.
3. 자기 차례에 가운데 더미에서 타일 1개를 뽑고, 상대의 숨은 타일 하나를 골라 숫자를 추리해요.
4. 맞히면 그 타일이 공개되고, 계속 추리하거나 멈출 수 있어요. 멈추면 뽑은 타일을 숨긴 채 자기 줄에 넣어요.
5. 틀리면 뽑은 타일을 공개한 채 자기 줄에 넣어요. 더미가 비어 있으면 대신 자기 숨은 타일 하나를 공개해요.
6. 타일이 모두 공개된 플레이어는 탈락하고, 마지막까지 남은 1명이 이겨요.

## 구현할 기능

우선순위가 높은 기능부터 차례로 만들어요. 상위 순위가 끝나기 전에 하위 순위를 먼저 만들지 않아요.

### 상: 2인 대전 (11월 말까지)

| 기능 | 내용 |
| --- | --- |
| 서버 접속·닉네임 | 서버 IP와 포트로 접속하고 닉네임을 등록해요 |
| 대기실 | 방을 만들고 입장해서 2명이 모이면 게임을 시작해요 |
| 타일 분배·정렬 | 서버가 24개 타일을 섞어 나눠 주고, 오름차순(같은 숫자면 검정이 왼쪽)으로 정렬해요 |
| 정보 은닉 | 각 클라이언트에는 자기 타일 숫자만 보내고, 상대의 숨은 타일은 색만 보내요 |
| 턴 진행 | 타일 뽑기 → 상대 타일 선택 → 숫자 추리 → 계속 또는 멈춤 순서로 진행해요 |
| 추리 판정 | 서버가 정답을 확인해 맞으면 상대 타일을, 틀리면 뽑은 타일을 공개해요 |
| 승패 판정 | 타일이 모두 공개되면 탈락하고, 마지막 1명이 이겨요. 결과 화면을 띄워요 |
| 마우스 조작 | 상대 타일을 클릭하고 숫자 버튼으로 추리해요 |

### 중: 다인원·채팅 (12월)

| 기능 | 내용 |
| --- | --- |
| 방 여러 개 | 방 목록에서 골라 입장하고, 방마다 게임이 따로 진행돼요 |
| 3~4인 모드 | 인원에 맞춰 시작 타일 수를 바꿔요 (4인은 3개) |
| 조커 타일 | 검정·흰 조커 2개를 추가하고, 원하는 자리에 놓을 수 있어요 |
| 채팅·이모티콘 | 대기실과 게임 중에 채팅하고 이모티콘을 보내요 |
| 턴 제한시간 | 시간 안에 추리하지 않으면 오답과 같이 처리해요 |
| 추리 기록 | 누가 어느 타일을 몇으로 추리했고 맞았는지 기록창에 보여 줘요 |
| 접속 끊김 처리 | 게임 중 나가면 기권으로 처리하고 남은 사람에게 알려요 |

### 하: 부가 기능 (12월)

| 기능 | 내용 |
| --- | --- |
| 추리 노트 | 정렬 규칙과 공개된 숫자로 각 숨은 타일에 올 수 있는 숫자 범위를 자동으로 표시해요 |
| 관전 모드 | 진행 중인 방에 들어가 공개된 정보만 봐요 |
| 전적·랭킹 | 서버 파일에 승패를 저장하고 랭킹을 보여 줘요 |
| 효과음·애니메이션 | 타일 공개, 정답·오답 순간을 연출해요 |

## 빌드와 실행

JDK 21 이상만 있으면 돼요. 외부 라이브러리와 빌드 도구(Maven, Gradle)는 쓰지 않아요.
소스는 `src/`, 컴파일 결과는 `bin/`에 생기고, `bin/`은 Git에 올리지 않아요.

```bash
javac --release 21 -encoding UTF-8 -d bin $(find src -name "*.java")
java -cp bin <메인 클래스의 전체 이름>
```

서버를 먼저 띄운 뒤 클라이언트를 여러 개(최대 4개) 실행해서 시험해요. 레포 최상위 폴더에서 실행해요.

```bash
java -Dstdout.encoding=UTF-8 -cp bin davinci.server.GameServer        # 서버 (기본 포트 30000, 다른 포트는 뒤에 숫자로)
java -cp bin davinci.client.ui.ClientMain                             # 클라이언트 (접속 창에서 주소·포트·닉네임 입력)
```

시험 코드는 `test/`에 있어요. 테스트 프레임워크 없이 `main`으로 돌려요.

```bash
javac --release 21 -encoding UTF-8 -d bin $(find src test -name "*.java")
java -Dstdout.encoding=UTF-8 -cp bin davinci.ChatTest                 # 화면 없이 소켓으로 채팅 기능 검사
java -cp bin davinci.client.ui.Shots shots                            # 창 3개로 채팅한 뒤 화면을 shots/에 저장
```

Eclipse에서는 이 폴더를 기존 프로젝트로 가져오면 돼요(`.project`, `.classpath` 포함). 인코딩은 UTF-8, Java Compiler 준수 수준은 21로 맞춰요.

## 구조

```
src/davinci/
├─ common/     서버와 클라이언트가 함께 쓰는 것: 타일 모델, 정렬 규칙, 프로토콜 메시지
├─ server/     서버 메인, 접속 관리(클라이언트마다 스레드), 방·대기실, 게임 상태와 규칙 판정
└─ client/     클라이언트 메인, 서버 연결과 메시지 송수신
   └─ ui/      Swing 화면: 접속, 대기실, 게임판, 결과
test/davinci/  시험 코드 (ChatTest, Shots)
```

- **서버가 판정해요.** 타일 섞기·분배·정렬, 추리 판정, 탈락과 승패는 모두 서버가 정하고, 클라이언트는 입력을 보내고 화면을 그리기만 해요.
- **정보를 숨겨요.** 상대의 숨은 타일은 색만 보내고 숫자는 보내지 않아요.
- **방마다 게임이 따로 돌아요.** 게임 상태는 방 단위로 둬요.
- 클라이언트는 소켓을 따로 만든 수신 스레드에서 읽고, 화면은 Swing 이벤트 스레드에서만 바꿔요.
- 서버와 클라이언트는 `writeUTF`/`readUTF`로 `/명령어 값1 값2 …` 형식의 메시지를 하나씩 주고받아요 (예: `/JOIN 홍길동`, `/GUESS 5 1 2`).

서버와 클라이언트의 역할, 모든 메시지 형식과 예시, 오류 코드, 정보 은닉 확인 목록은 [docs/PROTOCOL.md](docs/PROTOCOL.md)에 있어요.

## 이미지와 음성 파일

저작권 문제가 있을 수 있어서 이미지와 음성 파일은 **GitHub에 올리지 않아요.** 각자 자기 PC의 `assets/` 폴더에 두고 실행해요.

```
assets/
├─ images/   이미지
└─ sounds/   효과음
```

`assets/` 폴더와 이미지·음성 확장자는 `.gitignore`에 들어 있어요. 파일은 팀원끼리 메신저나 드라이브로 주고받아요.
파일이 없어도 게임은 돌아가요. 이미지 대신 색과 글자로 그리고, 소리 없이 진행해요.

## 개발 규칙

| 브랜치 | 용도 |
| --- | --- |
| `main` | 시연과 제출용. `dev`에서만 머지해요 |
| `dev` | 개발 중인 기능을 모으는 곳. 항상 빌드되고 실행되는 상태로 둬요 |
| `feat/<기능>`, `fix/<내용>`, `docs/<내용>` | 최신 `dev`에서 만들고, 끝나면 `dev`로 PR을 올려요 |

- PR은 다른 팀원이 확인한 뒤 머지해요.
- 커밋 메시지는 `종류: 내용` 형식이에요. 종류는 `feat`, `fix`, `refactor`, `docs`, `chore` 중 하나예요 (예: `feat: 대기실 방 만들기`).

## 규칙과 디자인에 대해

보드게임 "다빈치 코드"의 숫자 타일 추리 규칙을 바탕으로 직접 구현해요. 네트워크프로그래밍 수업 프로젝트 제출용이고, 판매나 배포를 위한 프로그램이 아니에요.
