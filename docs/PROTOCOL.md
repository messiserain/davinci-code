# 서버·클라이언트 역할과 통신 프로토콜

다빈치 코드 온라인(팀 stim)의 서버와 클라이언트가 맡을 일, 그리고 둘이 주고받는 메시지를 정리한 문서다.
각 메시지 옆의 **[상] [중] [하]** 는 CLAUDE.md의 기능 우선순위이고, [상]부터 차례로 만든다.

---

## 1. 서버와 클라이언트의 역할

기본 원칙: **서버가 판정하고, 클라이언트는 입력을 보내고 화면을 그린다.** 클라이언트는 받은 정보만으로 화면을 그리며, 규칙 판정 결과를 스스로 정하지 않는다.

| 구분 | 서버 (`davinci.server`) | 클라이언트 (`davinci.client`, `davinci.client.ui`) |
|---|---|---|
| 접속 | `ServerSocket`으로 접속을 받고, 클라이언트마다 스레드를 하나씩 만든다 | 서버 IP·포트로 접속하고, 수신 전용 스레드를 띄운다 |
| 사용자 | 닉네임 규칙과 중복을 검사하고, 플레이어 ID를 배정한다 | 닉네임을 입력받아 보낸다 |
| 대기실 | 방 만들기·입장·나가기·준비·시작을 처리하고, 방 목록을 바뀔 때마다 보낸다 | 방 목록과 방 안 참가자를 그리고, 버튼 입력을 메시지로 보낸다 |
| 게임 상태 | 방마다 게임 상태를 따로 가진다. 타일 24개(조커 사용 시 26개)를 섞고, 나눠 주고, 정렬한다 | 받은 `/STATE`대로 게임판을 다시 그린다 |
| 턴 진행 | 지금 단계와 차례를 관리하고, 차례가 아닌 사람의 요청이나 단계에 맞지 않는 요청은 거절한다 | 내 차례·단계에 맞는 버튼만 켠다 (편의용일 뿐, 최종 검사는 서버가 한다) |
| 판정 | 추리 정답 여부, 타일 공개, 뽑은 타일 넣기, 탈락, 승패, 순위를 정한다 | 결과를 받아 애니메이션·기록창·결과 화면으로 보여 준다 |
| 정보 은닉 | 받는 사람마다 따로 `/STATE`를 만든다. 남의 숨은 타일은 **색만** 넣고 숫자는 절대 넣지 않는다 | 자기에게 온 정보만 쓴다. 숨은 타일 숫자를 알 방법이 없다 |
| 시간 제한 [중] | 단계마다 타이머를 돌리고, 시간이 지나면 대신 진행한다 (뽑기 → 무작위 색, 추리 → 오답 처리, 계속/멈춤 → 멈춤) | 남은 시간을 표시한다 |
| 채팅 [중] | 로비 채팅은 로비 사람에게, 방 채팅은 방 사람에게 전달한다. 글자 수를 자른다 | 입력창과 채팅창, 이모티콘 버튼 |
| 끊김 [중] | 연결이 끊긴 사람을 기권 처리하고 남은 사람에게 알린다. 1명만 남으면 게임을 끝낸다 | 연결이 끊기면 안내하고 접속 화면으로 돌아간다 |
| 추리 노트 [하] | (없음) | 정렬 규칙과 공개된 숫자로 숨은 타일마다 올 수 있는 숫자 범위를 계산해 보여 준다 |
| 관전 [하] | 관전자에게는 공개된 타일만 담은 `/STATE`를 보낸다 | 조작 버튼 없이 게임판만 그린다 |
| 전적 [하] | 게임 결과를 서버 파일에 저장하고, 요청하면 랭킹을 보낸다 | 랭킹 화면을 그린다 |
| 효과음 [하] | (없음) | `assets/sounds/`의 파일을 재생한다. 없으면 소리 없이 진행 |

### 스레드 구성

- **서버**: 접속 대기 스레드 1개 + 클라이언트마다 수신 스레드 1개. 같은 방의 게임 상태를 여러 스레드가 동시에 고치지 않도록 방(또는 게임 상태) 단위로 `synchronized` 한다.
- **클라이언트**: EDT(화면) + 수신 스레드 1개. 수신 스레드가 `readUTF`로 받은 메시지는 `SwingUtilities.invokeLater`로 화면에 넘긴다. 보내기도 EDT를 막지 않도록 따로 처리한다.

## 2. 메시지 공통 형식

- TCP 소켓에서 `DataOutputStream.writeUTF` / `DataInputStream.readUTF`로 **메시지 하나씩** 주고받는다.
- 형식: `/명령어 값1 값2 …` — 명령어와 값은 **공백 한 칸**으로 나눈다.
- 공백이 들어갈 수 있는 값(채팅 내용, 방 제목, 안내 문구)은 **항상 마지막 값**에 둔다. 받는 쪽은 `split(" ", 값개수)`로 나눠서 마지막 값을 통째로 읽는다.
- 목록 값은 항목을 `|`로, 항목 안의 값을 `,`로 나눈다. 타일 줄 안의 타일은 `-`로 나눈다.
- 닉네임에는 공백·`|`·`,`·`-`를 쓸 수 없다 (2~10글자). 방 제목·채팅에서는 서버가 `|`, `,`를 지운다.
- 값이 비어 있으면 `-`를 쓴다 (예: 비밀번호 없음, 뽑은 타일 없음).
- 명령어 이름과 형식은 `davinci.common`의 한 클래스(예: `Protocol`)에 상수로 모아서 서버와 클라이언트가 같이 쓴다.

### 타일 표기

| 표기 | 뜻 |
|---|---|
| `B5` | 검은 5 (내 타일이라 숫자를 앎, 아직 숨겨짐) |
| `W11*` | 흰 11, 공개됨 (`*`는 모두에게 공개된 타일) |
| `B?` | 숫자를 모르는 검은 타일 (남의 숨은 타일) |
| `WJ` / `BJ` | 흰/검은 조커 [중] |

- **자리번호**는 그 플레이어 타일 줄의 왼쪽부터 0, 1, 2 … 로 센다. 타일이 들어오면 번호가 바뀌므로 클라이언트는 항상 마지막으로 받은 `/STATE` 기준으로 번호를 보낸다.

### 게임 단계

| 단계 | 뜻 | 이 단계에서 받는 요청 |
|---|---|---|
| `DRAW` | 차례인 사람이 더미에서 뽑을 차례 | `/DRAW` |
| `JOKER` [중] | 뽑은 조커를 놓을 자리를 고를 차례 | `/JOKER` |
| `GUESS` | 상대 타일 하나를 골라 추리할 차례 | `/GUESS` |
| `CONTINUE` | 맞힌 뒤, 계속 추리할지 멈출지 고를 차례 | `/GUESS`(계속) 또는 `/STOP` |
| `REVEAL_SELF` | 틀렸는데 더미가 비어서 내 숨은 타일 하나를 공개할 차례 | `/REVEAL` |
| `OVER` | 게임 끝 | 없음 |

## 3. 통신 프로토콜

### 3-1. 접속과 사용자 등록 [상]

| 기능 | 프로토콜 | 프로토콜 형식 | 실제 예시 | 각 값의 의미 | 전송 방향 | 전송 시점 | 수신 후 처리 |
|---|---|---|---|---|---|---|---|
| 게임 참가 요청 | `/JOIN` | `/JOIN 닉네임` | `/JOIN 홍길동` | 닉네임: 참가자의 사용자 이름(2~10글자) | 클라이언트 → 서버 | 서버에 접속한 직후, 닉네임을 입력하고 접속 버튼을 눌렀을 때 | 닉네임 규칙·중복 확인 → 실패하면 `/ERROR` → 성공하면 사용자 등록, 플레이어 ID 배정, `/WELCOME`과 `/LOBBY` 전송 |
| 참가 승인 | `/WELCOME` | `/WELCOME 플레이어ID 닉네임` | `/WELCOME 3 홍길동` | 플레이어ID: 서버가 배정한 번호 / 닉네임: 등록된 이름 | 서버 → 클라이언트 | `/JOIN`이 성공했을 때 | 내 ID를 저장하고 대기실 화면으로 전환 |
| 오류 알림 | `/ERROR` | `/ERROR 코드 안내문구` | `/ERROR NAME_TAKEN 이미 쓰고 있는 닉네임입니다.` | 코드: 오류 종류(아래 표) / 안내문구: 화면에 그대로 보여 줄 한국어 문장 | 서버 → 클라이언트 | 요청이 규칙에 어긋나 거절할 때 | 안내문구를 대화상자로 띄우고, 화면은 그대로 둔다 |
| 접속 종료 | `/QUIT` | `/QUIT` | `/QUIT` | 없음 | 클라이언트 → 서버 | 사용자가 창을 닫거나 접속 끊기를 눌렀을 때 | 방에 있으면 `/LEAVE`와 같이 처리(게임 중이면 기권) → 사용자 목록에서 지우고 소켓을 닫음 |

### 3-2. 대기실과 방 [상] (방 여러 개·인원·비밀번호·제한시간은 [중])

| 기능 | 프로토콜 | 프로토콜 형식 | 실제 예시 | 각 값의 의미 | 전송 방향 | 전송 시점 | 수신 후 처리 |
|---|---|---|---|---|---|---|---|
| 방 목록 | `/LOBBY` | `/LOBBY 방목록` (방목록 = `방번호,현재인원,최대인원,상태,잠김,제목` 을 `\|`로 이음) | `/LOBBY 1,1,2,WAIT,0,초보만 오세요\|2,4,4,PLAY,1,고수방` | 방번호: 방 ID / 상태: `WAIT`(대기)·`PLAY`(게임 중) / 잠김: 비밀번호 있으면 1 / 제목: 방 제목. 방이 없으면 `-` | 서버 → 클라이언트 | 등록 직후, 그리고 방이 생기거나 없어지거나 인원·상태가 바뀔 때 로비에 있는 모두에게 | 대기실의 방 목록을 다시 그림 |
| 방 만들기 | `/CREATE` | `/CREATE 최대인원 제한시간 비밀번호 제목` | `/CREATE 2 30 - 초보만 오세요` | 최대인원: 2~4 ([상]에서는 2) / 제한시간: 단계당 초, 0은 무제한 / 비밀번호: 없으면 `-` / 제목: 방 이름(공백 가능) | 클라이언트 → 서버 | 대기실에서 방 만들기 창을 채우고 확인을 눌렀을 때 | 값 범위 확인 → 방 번호 배정, 만든 사람을 방장으로 넣음 → 그 사람에게 `/ROOM`, 로비 모두에게 `/LOBBY` |
| 방 입장 | `/ENTER` | `/ENTER 방번호 비밀번호` | `/ENTER 1 -` | 방번호: 들어갈 방 / 비밀번호: 없으면 `-` | 클라이언트 → 서버 | 방 목록에서 방을 골라 입장을 눌렀을 때 | 방 존재·인원·게임 중 여부·비밀번호 확인 → 실패하면 `/ERROR` → 성공하면 방에 추가, 방 안 모두에게 `/ROOM`, 로비에 `/LOBBY` |
| 방 정보 | `/ROOM` | `/ROOM 방번호 방장ID 최대인원 제한시간 참가자목록 제목` (참가자목록 = `ID,닉네임,준비` 를 `\|`로 이음) | `/ROOM 1 3 2 30 3,홍길동,0\|5,김철수,1 초보만 오세요` | 방장ID: 방장의 플레이어 ID / 준비: 1이면 준비 완료 / 나머지는 `/CREATE`와 같음 | 서버 → 클라이언트 | 방에 들어갔을 때, 방 안의 누가 들어오거나 나가거나 준비를 바꿀 때 방 안 모두에게 | 방 화면으로 전환(이미 방이면 갱신), 참가자 자리와 준비 표시, 내가 방장이면 시작 버튼 표시 |
| 준비 | `/READY` | `/READY 준비여부` | `/READY 1` | 준비여부: 1 준비, 0 취소 | 클라이언트 → 서버 | 방에서 준비 버튼을 누르거나 다시 눌러 취소할 때 | 그 사람의 준비 상태를 바꾸고 방 안 모두에게 `/ROOM` |
| 게임 시작 | `/START` | `/START` | `/START` | 없음 | 클라이언트 → 서버 | 방장이 시작 버튼을 눌렀을 때 | 방장인지, 2명 이상인지, 방장 외 모두 준비했는지 확인 → 게임 상태를 만들고 타일을 섞어 나눠 주고 정렬 → `/GAMESTART`, 각자에게 `/STATE`, `/TURN` |
| 방 나가기 | `/LEAVE` | `/LEAVE` | `/LEAVE` | 없음 | 클라이언트 → 서버 | 방에서 나가기 버튼을 눌렀을 때 | 게임 중이면 기권 처리(`/FORFEIT`) → 방에서 빼고 본인에게 `/LEFT`, 방에 `/ROOM`, 로비에 `/LOBBY`. 방장이 나가면 남은 사람에게 방장을 넘기고, 아무도 없으면 방을 지움 |
| 방에서 나감 | `/LEFT` | `/LEFT 안내문구` | `/LEFT 방에서 나왔습니다.` | 안내문구: 나간 이유 | 서버 → 클라이언트 | 본인이 `/LEAVE`를 보냈거나 방이 없어졌을 때 | 대기실 화면으로 전환하고 안내문구 표시 |

### 3-3. 게임 진행 [상] (조커는 [중])

| 기능 | 프로토콜 | 프로토콜 형식 | 실제 예시 | 각 값의 의미 | 전송 방향 | 전송 시점 | 수신 후 처리 |
|---|---|---|---|---|---|---|---|
| 게임 시작 알림 | `/GAMESTART` | `/GAMESTART 순서목록` (순서목록 = `ID,닉네임` 을 `\|`로 이음) | `/GAMESTART 3,홍길동\|5,김철수` | 순서목록: 차례 순서대로 나열한 플레이어 | 서버 → 클라이언트 | `/START`가 성공했을 때 방 안 모두에게 | 게임판 화면으로 전환하고 자리 배치 |
| 게임 상태 | `/STATE` | `/STATE 단계 차례ID 검정더미 흰더미 남은초 뽑은타일 자리목록` (자리목록 = `ID,생존,타일들` 을 `\|`로 이음, 타일들은 `-`로 이음) | (3번이 받는 것) `/STATE GUESS 3 7 8 25 W8 3,1,B0-W3*-B7-B9\|5,1,W?-B?-B5*-W?`<br>(5번이 받는 것) `/STATE GUESS 3 7 8 25 W? 3,1,B?-W3*-B?-B?\|5,1,W1-B2-B5*-W10` | 단계: 위 단계 표 / 차례ID: 지금 차례인 사람 / 검정더미·흰더미: 더미에 남은 수 / 남은초: 이 단계 남은 시간, 무제한이면 0 / 뽑은타일: 이번 차례에 뽑은 타일, 없으면 `-` / 생존: 1 살아 있음, 0 탈락 / 타일들: 타일 표기 | 서버 → 클라이언트 | 게임 시작 직후, 그리고 게임 상태가 바뀔 때마다 방 안 **한 사람씩 따로** | 게임판 전체를 이 내용대로 다시 그림. 내 차례·단계에 맞는 버튼만 켬. **서버는 받는 사람 본인의 타일과 공개된 타일에만 숫자를 넣는다** |
| 차례 알림 | `/TURN` | `/TURN 플레이어ID` | `/TURN 3` | 플레이어ID: 이번 차례인 사람 | 서버 → 클라이언트 | 새 차례가 시작될 때 방 안 모두에게 | 차례 표시, 내 차례면 알림 |
| 타일 뽑기 | `/DRAW` | `/DRAW 색` | `/DRAW W` | 색: `B` 검정 더미, `W` 흰 더미 | 클라이언트 → 서버 | 내 차례 `DRAW` 단계에서 더미를 클릭했을 때 | 차례·단계·더미 남은 수 확인 → 그 색 더미에서 무작위로 한 장 꺼내 뽑은 타일로 둠 → 조커면 `JOKER`, 아니면 `GUESS` 단계로 → 모두에게 `/STATE` (뽑은 사람만 숫자를 봄). 두 더미가 모두 비었으면 뽑지 않고 바로 `GUESS` |
| 조커 놓기 [중] | `/JOKER` | `/JOKER 자리번호` | `/JOKER 2` | 자리번호: 내 줄에서 조커를 끼워 넣을 위치 | 클라이언트 → 서버 | `JOKER` 단계에서 내 줄의 틈을 클릭했을 때 | 자리 범위 확인 → 조커를 놓을 위치를 기억(실제로 줄에 넣는 것은 차례가 끝날 때) → `GUESS` 단계로, 모두에게 `/STATE` |
| 숫자 추리 | `/GUESS` | `/GUESS 대상ID 자리번호 숫자` | `/GUESS 5 1 2` | 대상ID: 추리할 상대 / 자리번호: 상대 줄에서 고른 타일 위치 / 숫자: 0~11, 조커는 `J` | 클라이언트 → 서버 | `GUESS` 또는 `CONTINUE` 단계에서 상대 타일을 클릭하고 숫자 버튼을 눌렀을 때 | 차례·단계 확인, 대상이 살아 있는 상대인지, 그 타일이 숨겨져 있는지 확인 → 정답이면 타일 공개, `CONTINUE` 단계로 / 오답이면 뽑은 타일을 공개한 채 내 줄에 넣음(더미가 비어 뽑은 게 없으면 `REVEAL_SELF`) → `/GUESSED`, 탈락 확인, 모두에게 `/STATE` |
| 추리 결과 | `/GUESSED` | `/GUESSED 추리자ID 대상ID 자리번호 숫자 결과` | `/GUESSED 3 5 1 2 OK` | 결과: `OK` 정답, `NO` 오답 / 나머지는 `/GUESS`와 같음 | 서버 → 클라이언트 | `/GUESS`를 판정한 직후 방 안 모두에게 | 맞힘/틀림 애니메이션, 추리 기록창에 한 줄 추가 |
| 멈추기 | `/STOP` | `/STOP` | `/STOP` | 없음 | 클라이언트 → 서버 | 맞힌 뒤 `CONTINUE` 단계에서 멈추기 버튼을 눌렀을 때 | 차례·단계 확인 → 뽑은 타일을 **숨긴 채** 정렬 규칙에 맞는 자리(조커는 고른 자리)에 넣음 → `/PLACED` → 다음 사람 차례로, `/TURN`, 모두에게 `/STATE` |
| 내 타일 공개 | `/REVEAL` | `/REVEAL 자리번호` | `/REVEAL 0` | 자리번호: 공개할 내 숨은 타일 위치 | 클라이언트 → 서버 | 오답인데 더미가 비어 있어 `REVEAL_SELF` 단계가 됐을 때, 내 타일을 클릭했을 때 | 그 타일이 내 숨은 타일인지 확인 → 공개 → 탈락 확인 → 다음 차례로, `/TURN`, 모두에게 `/STATE` |
| 타일 넣음 알림 | `/PLACED` | `/PLACED 플레이어ID 자리번호 공개여부` | `/PLACED 3 2 0` | 자리번호: 뽑은 타일이 들어간 위치 / 공개여부: 1 공개해서 넣음(오답), 0 숨겨서 넣음(멈춤) | 서버 → 클라이언트 | 뽑은 타일을 줄에 넣은 직후 방 안 모두에게 | 타일이 들어가는 애니메이션과 기록 |
| 탈락 | `/ELIM` | `/ELIM 플레이어ID` | `/ELIM 5` | 플레이어ID: 타일이 모두 공개된 사람 | 서버 → 클라이언트 | 누군가의 타일이 모두 공개됐을 때 방 안 모두에게 | 그 자리를 탈락으로 표시 |
| 게임 종료 | `/GAMEOVER` | `/GAMEOVER 순위목록` (순위목록 = `순위,ID,닉네임` 을 `\|`로 이음) | `/GAMEOVER 1,3,홍길동\|2,5,김철수` | 순위: 1이 승자. 먼저 탈락할수록 뒤 순위 | 서버 → 클라이언트 | 살아 있는 사람이 1명만 남았을 때 방 안 모두에게. 직전에 모든 타일을 공개한 `/STATE`를 보낸다 | 결과 화면으로 전환. 확인을 누르면 방 대기 화면으로. 서버는 방을 `WAIT`로 되돌리고 준비를 모두 풀고 `/ROOM`, `/LOBBY` 전송 |

## 5. 2인 대전 한 판의 메시지 흐름 (예)

```
A → S  /JOIN 홍길동                  S → A  /WELCOME 3 홍길동, /LOBBY -
B → S  /JOIN 김철수                  S → B  /WELCOME 5 김철수, /LOBBY -
A → S  /CREATE 2 30 - 한판해요       S → A  /ROOM 1 3 2 30 3,홍길동,0 한판해요   S → 로비  /LOBBY 1,1,2,WAIT,0,한판해요
B → S  /ENTER 1 -                    S → A,B  /ROOM …
B → S  /READY 1                      S → A,B  /ROOM …
A → S  /START                        S → A,B  /GAMESTART 3,홍길동|5,김철수
                                     S → A   /STATE DRAW 3 … (A의 숫자만 보임)
                                     S → B   /STATE DRAW 3 … (B의 숫자만 보임)
                                     S → A,B /TURN 3
A → S  /DRAW W                       S → A,B /STATE GUESS …  (뽑은 타일: A는 W8, B는 W?)
A → S  /GUESS 5 1 2                  S → A,B /GUESSED 3 5 1 2 OK, /STATE CONTINUE …
A → S  /STOP                         S → A,B /PLACED 3 4 0, /TURN 5, /STATE DRAW 5 …
   … 반복 …
                                     S → A,B /ELIM 5, /STATE OVER …(모두 공개), /GAMEOVER 1,3,홍길동|2,5,김철수
```

## 6. 정보 은닉 확인 목록

메시지를 새로 만들거나 고칠 때 아래를 확인한다.

- 남의 숨은 타일 숫자가 들어가는 메시지는 없다. `/STATE`는 받는 사람마다 따로 만든다.
- `/STATE`의 뽑은 타일은 뽑은 사람에게만 숫자를 넣는다.
- `/PLACED`는 숨겨서 넣은 타일의 숫자를 보내지 않는다 (자리번호만).
- `/GUESSED`의 숫자는 추리한 사람이 말한 값이라 모두에게 보여도 된다. 오답이면 진짜 숫자는 보내지 않는다.
- 관전자의 `/STATE`에는 공개된 타일만 숫자를 넣는다.
- 게임이 끝난 뒤(`OVER`)에만 모든 타일을 공개한다.
